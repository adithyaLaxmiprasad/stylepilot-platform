# How Things Work: StylePilot AI

This document explains the complete architecture and data flow of StylePilot AI, detailing how the different modules interact to provide a seamless, AI-powered personal styling experience.

## System Architecture

StylePilot AI operates on a modern, decoupled architecture split into three distinct layers:
1. **Frontend (`/frontend`)**: The user-facing application built with Next.js and React.
2. **Backend (`/backend`)**: An Express.js server that acts as an API gateway and handles file processing.
3. **AI Service (`/ai-service`)**: A dedicated Node.js module responsible for communicating with Google's Gemini AI.

---

## 1. The Frontend (Next.js & React)
**Directory:** `/frontend`

The frontend is responsible for the UI/UX, capturing user preferences, handling image uploads, and presenting the generated outfits.

### Key Components:
- **`app/page.tsx`**: The main hub of the application. It maintains the global state for the session (uploaded images, selected skin tone, occasion, color preference, generated results, and the FIFO style archive).
- **`components/ImageUpload.tsx`**: Handles the drag-and-drop or file selection of clothing images. It validates the input and prepares `File` objects.
- **`components/InputSelect.tsx` & `SkinToneGuide.tsx`**: Custom-built interactive UI elements that replace native browser inputs for a premium feel.
- **`components/InteractiveBackground.tsx` & `ClothesLoader.tsx`**: UI enhancements using `framer-motion` to provide high-end, smooth animations (cursor tracking glow and changing clothes loading indicator).

### Data Flow (Frontend to Backend):
When the user clicks "Generate Looks", the frontend packages all state into a `FormData` object (essential for sending binary image files alongside text data) and sends a `POST` request to the backend's `/api/generate` endpoint.

---

## 2. The Backend (Express.js)
**Directory:** `/backend`

The backend serves as a secure middleman. It prevents the frontend from communicating directly with the AI service, thereby protecting the API keys and allowing for server-side validation and file processing.

### Key Modules:
- **`index.js`**: Bootstraps the Express server, configures CORS (allowing the frontend to communicate with it), and mounts the routes.
- **`routes/generate.js`**: Defines the `/api/generate` endpoint. It uses the `multer` middleware (`upload.array("images", 5)`) to intercept the incoming request, extract the binary image files, and store them temporarily in memory (`req.files`).
- **`controllers/generateController.js`**: The brains of the backend route. 
  1. It extracts the text fields (skin tone, occasion, etc.) from `req.body`.
  2. It converts the buffered image files into Base64 encoded strings.
  3. It passes this structured data to the isolated AI Service.
  4. It catches the AI's response, attempts to parse the strict JSON output, and sends a sanitized response back to the frontend.

---

## 3. The AI Service
**Directory:** `/ai-service`

This is an isolated module specifically designed to handle the complexities of interacting with Large Language Models (LLMs), currently utilizing the `@google/genai` SDK.

### The Core Engine (`src/index.js`):
- **Initialization**: It initializes the Gemini client using the secure `GEMINI_API_KEY` from the `.env` file.
- **Prompt Engineering**: The `generateOutfits` function constructs a highly specific, system-level prompt. It explicitly instructs the AI on its persona ("elite luxury fashion stylist") and strictly enforces the output format to be a JSON array of objects.
- **Multimodal Payload**: It maps the Base64 image strings received from the controller into the specific `inlineData` format required by the Gemini Vision model.
- **Generation**: It invokes the `gemini-2.5-flash` model, passing both the images and the engineered text prompt. The model analyzes the textures and colors of the images alongside the user's text preferences to synthesize 5 distinct outfit combinations.
- **Return**: The raw, structured JSON string generated by the AI is returned to the backend controller for parsing and delivery.

---

## The Complete Lifecycle (Step-by-Step)
1. **User Interaction**: The user selects 3 photos of their clothes, picks "Medium" skin tone, "Night Out" occasion, and a dark hex color on the frontend.
2. **Submission**: The user clicks "Generate". The frontend bundles this into a `FormData` payload and POSTs it to `http://localhost:5000/api/generate`.
3. **Processing**: The backend `multer` middleware catches the photos and puts them in memory.
4. **Encoding**: The `generateController` converts those photos to Base64 strings.
5. **AI Request**: The AI service takes those Base64 strings and the text preferences, builds a strict prompt, and asks `gemini-2.5-flash` to act as a stylist.
6. **AI Response**: Gemini looks at the photos, thinks, and replies with a JSON string containing 5 outfits.
7. **Delivery**: The backend parses that JSON string and sends it back to the frontend with a `200 OK` status.
8. **Rendering**: The frontend removes the `ClothesLoader`, updates the result state, adds the first outfit to the horizontal "Style Archive", and smoothly animates the new `OutfitCard` components into view.
